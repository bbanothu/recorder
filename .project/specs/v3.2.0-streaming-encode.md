## Goal

Replace temp-file → WAV → one-shot ffmpeg with a live encode, so that:

- `/stop` no longer waits ~37 s per hour of meeting for its DM (README Known limits,
  measured on the 3.0.x path);
- the session's disk footprint collapses to the final `.ogg` instead of ~1.38 GB of
  float32 stereo mix per hour of elapsed wall time (4 bytes × 2 ch × 48 kHz × elapsed);
- the per-packet synchronous read-modify-write inside the voice packet callback
  (`src/master-mix.js:308-332`) disappears, which is what forces README's
  "keep `MEETINGS_DIR` on local disk" limit.

## Current pipeline (verified at 3.0.1)

- `push()` (`src/master-mix.js:120`) decodes Opus → snaps to the 20 ms grid →
  `#addAt()` (`:308`) does a positional `readSync`/`writeSync` read-modify-write into
  `master-<stamp>.mix.tmp` (named in `#ensureTemp`, `:291-299`) as interleaved **float32
  stereo**.
- `finalize()` (`:176`) streams that temp through `softLimitToInt16` (`:31`) into a WAV
  (`openStreamingWavWriter`, 256 KB chunks), unlinks the temp in a `finally`, then
  `encodeToOgg()` → `ffmpegWavToOgg` (`:421`) with `buildFfmpegArgs` (`:394`): `libopus`,
  explicit `-b:a $MASTER_BITRATE`, `-ar 48000`, `-ac 1`, `-application voip`.
- Contracts that must survive: `ioError` ⇒ no master while `packetCount`/`masterHadAudio`
  still distinguish a write failure from silence (`src/bot.js:501-512`, the defect Task 7b
  fixed); missing ffmpeg ⇒ keep `.wav`, never DM it (`src/deliver.js:140-147`); over-cap
  ⇒ never DM it (`src/deliver.js:148-153`).
- The frozen fixture `test/fixtures/master-mix-golden.wav` is an **int16 stereo 48 kHz
  PCM WAV** (RIFF/fmt PCM, 2 ch, 48000 Hz, 16-bit, 23040 data bytes = 5760 stereo
  frames = 115.2 s of the 20 ms grid) and `test/master-mix.test.mjs:233-243` asserts the
  finalize-produced WAV is **byte-identical** to it for a scripted packet sequence. That
  fixture is this release's strongest acceptance instrument.

## Target design

One long-lived ffmpeg per session, fed **s16le, 48 kHz, mono** PCM over stdin:

```
ffmpeg -hide_banner -loglevel error -f s16le -ar 48000 -ac 1 -i pipe:0 \
  -c:a libopus -b:a <MASTER_BITRATE> -application voip -f ogg <dir>/master-<stamp>.partial.ogg
```

Mix + soft-limit per 20 ms frame (already bounded to one frame buffer); ffmpeg does the
voip encode live. `/stop` = stop accepting, flush the current frame, `stdin.end()`, await
exit, rename `.partial.ogg` → `.ogg`.

### D1 — the timeline moves from file offsets to feed order (the crux)

Today the timeline is absolute: `offset = frameIndex × FRAME_SAMPLES × CHANNELS`, gaps are
sparse-file holes that read back as zeros (`src/master-mix.js:311`, `:319-323`). A pipe
cannot be seeked.

**Design: the mix becomes frame-oriented (one sequential cursor), with two sinks.**

```js
// sink interface — the only thing that differs between the streaming and legacy paths
//   writeFrame(frameIndex, s16Stereo /* Int16Array, 1920 samples = FRAME_SAMPLES*CHANNELS */)
//   finish() -> Promise<string|null>   abort() -> void
```

- `MasterMix.push()` keeps its decode + grid-snap + per-user monotonic clamp, then:
  - `frameIndex = max(round((atMs - t0)/20), state.lastFrame + 1)`;
  - if `frameIndex > this.curFrame`: flush `curFrame` to the sink, emit **zero frames** for
    every index in between, set `curFrame = frameIndex`, clear the frame accumulator;
  - add the packet's samples into `this.frameMix` — a **`Float32Array`** of one frame
    (1920 samples). Float32, not Float64: today's temp file rounds every add to float32,
    and the golden fixture has that rounding baked in.
- Flushing a frame applies `softLimitToInt16` per channel and downmixes:
  `mono = ((softLimitToInt16(L) + softLimitToInt16(R)) / 2) | 0` — the same order today's
  chain has (soft-limit each channel, then downmix). ffmpeg's own float downmix differs by
  ≤1 LSB; downmixing in JS is a deliberate, pinned change so the equivalence test is
  derivable from the stereo fixture.
- **Legacy sink** = today's `#addAt`/`#writeWav`/one-shot ffmpeg, preserving the sparse
  positional write for a sink that is fed sequentially but must keep absolute offsets.
  **Stream sink** = the ffmpeg child; it asserts it is fed strictly increasing frame
  indices and reports a counter when it is not.

**Acceptance before touching the real encoder is even needed:** the golden fixture.
For the scripted sequence in `test/master-mix.test.mjs`, the new path's **stereo**
soft-limited PCM stream must equal the fixture's `data` section byte-for-byte (that is
the timeline/gap proof), and the **mono** stream must equal the pinned downmix of it.
The legacy sink must still reproduce the fixture byte-for-byte through the existing test.

### D2 — backpressure, memory-bounded (adopted default)

`stdin.write()` returning `false` with an unbounded child buffer is the failure mode that
eats memory. The stream sink owns a pump:

- a FIFO of jobs: `{kind:'pcm', buf}` and `{kind:'zero', count}`;
- the pump writes while the child accepts, and waits for `'drain'` after a `false`;
- **zero runs are counts, not buffers** (one reused 1920-byte zero frame is written
  repeatedly): a 10-minute silence gap costs no memory, and it drains in seconds because
  ffmpeg encodes ~100× realtime;
- `pendingPcmBytes` bounds only real PCM: when a new PCM frame would exceed
  `MAX_PENDING_PCM_BYTES` (**4 MiB**, ≈ 42 s of mono s16), the frame's **content is
  replaced by silence** (a zero frame) and `droppedPcmFrames` is incremented + logged once
  per session. The **timeline is never broken** — a dropped frame still advances the
  cursor, so no transcript timestamp after it shifts. A true skip would shift every later
  timestamp, so it is not offered.
- `push()` never blocks, never awaits, and never throws into the voice callback: the pump
  is a detached async loop whose rejections are logged (mirroring the existing
  `hookFailed` isolation in `src/recorder.js:95-104`).
- The counter and the cap are exported constants; the cap is a policy knob, not a magic
  number. ffmpeg's stderr is piped and drained into a bounded (≤8 KB) buffer for the
  failure message — an undrained stderr pipe would stall the child.

### D3 — child death mid-session: fall back to the legacy path (adopted default)

On `'error'` or a non-zero `'exit'` **while the session is live and frames are still
arriving**:

1. log loudly, with the exit code and the drained stderr tail, and set
   `streamFailed = true`;
2. switch the sink to a **legacy sink seeded at the current absolute frame index** so the
   remaining audio lands at its correct offsets — the already-streamed prefix is lost and
   the output therefore has a **silent prefix**;
3. unlink the partial file (two masters cannot be merged);
4. continue the session; `finalize()` then runs the legacy chain and delivery proceeds
   normally, with one extra log line naming the prefix loss and `encodeState()`
   reporting `{ alive: false, fallback: true }`.

**This degradation is documented, not papered over:** the alternative in the brief
(abort the master and take the existing "master write failed" reply) throws away a
two-hour meeting's audio, and restart-and-concat needs Ogg page surgery this release does
not take on. The spec, README and CHANGELOG all state the silent-prefix consequence. The
fallback path is the already-written, already-tested 3.0.x code, which is why it is the
cheap correct answer.

### D4 — unclean exit at finish: salvage the partial (adopted default)

At `finish()`: `stdin.end()`, await `'exit'` with a bounded deadline
(`STREAM_EXIT_TIMEOUT_MS`, 10 s). If the child exited non-zero (or the deadline fired and
it was killed), the partial file is **renamed to the final `.ogg`** anyway — an Ogg is
playable to its last complete page — and a truncation line is logged. A
`master-<stamp>.partial.ogg` is **never** handed to `deliver.js`: `.ogg`-ness is
`deliver.js`'s signal for "sendable" (`src/deliver.js:140-147`) and a `.partial.ogg` must
not be mistaken for a finished file. Pin both halves.

### D5 — ffmpeg is probed at session start (behind a DI seam)

Today a missing ffmpeg is discovered at finalize and degrades to a `.wav`. With a live
child it must be known at session start: `MasterMix.start()` runs an injectable probe
(`deps.probeFfmpeg ?? defaultProbeFfmpeg`, a bounded `ffmpeg -version` invocation) and, on
failure, selects the **legacy sink for the whole session** and logs one line. The probe is
never run in tests (`deps.probeFfmpeg` is stubbed) and its cost (~50 ms, once per session,
on the `/record` path) is stated in the README.

### D6 — the 25 MB cap: accepted, and the cap-aware bitrate fix is separated

With a live encode the bitrate is fixed at session start, so v3.1.0's Tier-1 #5 ("pick the
encode bitrate at finalize from elapsed duration") has no finalize hook on the streaming
path.

**Decision: accept it.** An over-cap master keeps today's behaviour — it stays on disk,
never DM'd — with no new per-guild state and no re-encode machinery. The cap-aware bitrate
change is **out of this release** and lands separately on the legacy path if it is still
wanted. Shipping a bitrate rule that only applies to the fallback path would contradict
itself, so it is explicitly not done here. Worst case is unchanged and documented: 24k
Opus mono ≈ 10.8 MB/h continuous audio (SETUP.md), ~2.4 h to the cap.

### D7 — late and jittered packets (adopted default)

Per-user frames are clamped monotonic today (`src/master-mix.js:148-154`), which on a
sparse file can *backfill* a hole. A pipe cannot rewind. Policy:

- clamp exactly as today (`state.lastFrame + 1`);
- if the resulting index is still **behind** the feed cursor `curFrame`, merge it forward
  into the next unwritten frame (≤20 ms of timing error);
- if it is behind by more than `LAG_TOLERANCE_FRAMES = 5` (100 ms), **drop it** with one
  log line per session and count it (`lateDroppedFrames`);
- `finalize()` logs the session's `lateDroppedFrames` / `droppedPcmFrames`, and Task 6's
  measurement harness reports the observed late-frame rate for a real 1 h session — the
  number is **measured, never estimated**. If it proves non-trivial, this policy is the
  button to revisit, and the measurement is the evidence that would justify revisiting it.

### D8 — `/status` interaction (the 3.1.0 seam)

3.1.0 ships `/status` reading `master.encodeState?.()` with a v3.0.x fallback. 3.2.0 fills
it: `encodeState()` → `{ framesFed, outputBytes, alive, fallback }` (`alive` false after a
child death; `fallback` true when the legacy sink took over; `outputBytes` from
`statSync(partialOrFinalPath).size` in a try/catch, `null` on failure). 3.1.0's `/status`
keeps working with 3.2.0's value without changes — that is the compatibility claim this
seam exists for, and Task 7 verifies it by running `/status` on both shapes.

### D9 — crash safety and shutdown

- The in-progress file is `master-<stamp>.partial.ogg`; renamed to `master-<stamp>.ogg` on
  clean exit.
- `src/tmp-cleanup.js` gains `PARTIAL_OGG_SUFFIX = '.partial.ogg'` and sweeps that residue
  at startup next to the existing `*.mix.tmp` sweep — **never a finished `.ogg`** (the
  suffix test is exact, not a substring test on `.ogg`).
- A bounded SIGTERM handler in `index.js`: log, end the encoder's stdin, wait up to
  `SIGTERM_GRACE_MS` (3 s) for the child, then `process.exit(0)`; the same logic lives in
  a unit-testable function in `src/stream-encode.js`. Best-effort under compose's
  `init: true` (tini) — stated as such, and the startup sweep covers the kill-9 case.

## Hard constraints (AGENTS.md, non-negotiable)

Mono + `-application voip` + `-b:a MASTER_BITRATE` stay. Never re-add stereo or
generic-audio mode "for quality" — it triples size and the 25 MB cap is the constraint.
`deliver.js`'s `masterHadAudio` contract survives in a new form: "did we ever feed a
non-silent frame", still distinguishing silence from failure. Audio changes require
**measured** output size and wall time — no hand-back estimates. Agents commit on the
feature branch only; the user merges.

## Acceptance criteria

- **AC1** For the scripted packet sequence of `test/master-mix.test.mjs`, the streaming
  path's soft-limited **stereo** PCM stream is byte-identical to
  `test/fixtures/master-mix-golden.wav`'s data section, and its **mono** stream is
  byte-identical to the pinned downmix of it.
- **AC2** The legacy sink still reproduces the fixture byte-for-byte (the existing test is
  unchanged and green).
- **AC3** Timeline/gap correctness with an injected clock: a gap between two packets
  produces exactly `floor(gap/20 ms)` zero frames, and the first packet after the gap
  lands on the grid index its timestamp implies.
- **AC4** Backpressure: a fake child that accepts N frames then stalls never blocks or
  throws in `push()`; once `pendingPcmBytes` exceeds the cap, further frames are written
  as **silence** with the cursor still advancing (no timeline shift) and the drop counter
  incremented; a long zero run consumes no per-byte memory (asserted by a large gap).
- **AC5** Child death mid-session: the session continues, the remainder is produced by the
  legacy path with correct absolute offsets (silent prefix), the partial is unlinked, the
  drop/fallback counters and one log line are present, and delivery still runs the normal
  path.
- **AC6** Unclean exit at `finish()`: the partial is renamed to the final `.ogg`, a
  truncation line is logged, and `deliver.js` receives a `.ogg` (never a `.partial.ogg`).
- **AC7** Missing ffmpeg (probe stubbed false): the legacy path is selected at session
  start, one log line is emitted, and the existing `.wav`-never-DM'd behaviour holds.
- **AC8** `ioError` semantics: a session whose master could not be produced still reports
  `masterWriteFailedText`, and a genuinely silent session still reports "Nobody spoke" —
  the `masterHadAudio` read (`src/bot.js:501-512`) is preserved in its new form.
- **AC9** `encodeState()` returns `{ framesFed, outputBytes, alive, fallback }` in every
  state (live, fallback, finished, failed) and `/status` renders it, with and without the
  method present (the 3.1.0 fallback still works).
- **AC10** Startup sweep removes `*.partial.ogg` residue and never touches a finished
  `.ogg`; the SIGTERM handler ends stdin, waits boundedly, exits, and never hangs.
- **AC11** **Measured**, on a real 1-hour synthetic session with ffmpeg present: peak
  intermediate disk < ~100 MB (target; report the observed number), `/stop` → DM latency
  is encode-free (report the observed ms), the output `.ogg` is within a few percent of
  the pre-change size for the same content, and the late-frame rate is reported. The
  command is committed as `scripts/measure-stream-encode.mjs` so the number is
  reproducible; the observation is written into this spec's Measurements section.
- **AC12** `package.json` 3.2.0 + matching CHANGELOG heading + README (the ~37 s/hour and
  "local disk only" limits are **replaced by the measured numbers**, not deleted
  silently) + SETUP updates in the release commit; `npm test` green.

## Out of scope

- Tier-1 #4 — per-user frames buffered in RAM until finalize (`src/recorder.js:85-90`,
  `:170-175`). It is the same class of problem and a natural 3.3.0 candidate.
- Tier-1 #5 — cap-aware bitrate (D6).
- Ogg page surgery / chunked-encode concatenation (brief option D), which is the only way
  to avoid the silent prefix on a child death.
- Any change to the DM policy, the transcription sidecar, or the per-user track pipeline.

## Risks

- **Timeline regressions are silent** (a wrong offset still produces a playable file). The
  golden equivalence test (AC1/AC2/AC3) is the only guard that catches this before a user
  does; it is not optional.
- **A child that dies is now a mid-session event** rather than a finalize-time one: the
  fallback is the mitigation, and AC5 pins it.
- **Downmix moved into JS** (≤1 LSB from ffmpeg's) — pinned by AC1 and stated in the PR.
- **Windows dev / Linux prod**: the streaming path uses pipes and child process exits; both
  are exercised in Task 1's fake-child tests and Task 6's real ffmpeg run on the host.
- **`process.on('SIGTERM')` in a Docker container** relies on `init: true` forwarding;
  documented as best-effort with the startup sweep as the backstop.
