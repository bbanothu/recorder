## Goal

Six autonomous-operating hazards a self-hosted recorder is actually bitten by: it can
record nothing without telling anyone (T1), it goes deaf and stale when the bot itself
is moved (T2), it keeps "recording" an empty channel for the rest of the auto-stop
threshold (T3), it never deletes anything (T4), it has no read-only view of its own
state (T5), and any guild member can start/stop recordings and change delivery settings
(T6). All six are contained changes to seams that already exist.

## Actors

- **Operator** — runs the bot, has `ManageGuild`, cares about disk, lost audio, and the
  channel notice telling the truth.
- **Guild member** — may speak in a recording; from 3.1.0 may read `/status` and
  `/help`, and may `/stop` a session they started.
- **The bot process** — one session at a time, gateway-liveness first (see AGENTS.md:
  a dead process loses live recordings, so no new failure path may crash the gateway).

## Key decisions

### D1 — Voice-connection loss is observed (T1, user-approved)

- `bot.js` imports `VoiceConnectionStatus` only for the initial
  `entersState(connection, Ready, 20_000)` (`src/bot.js:224`). **Verified: there is no
  `connection.on(...)` and no `stateChange` subscription anywhere in `src/`** (grep:
  zero matches for `stateChange`).
- Subscribe to `connection.on('stateChange', …)` at record time:
  - `Disconnected` → one `logEvent` + one `notifyChannel` line naming the reconnect
    window, set a **bounded 30 s deadline** (`VOICE_RECONNECT_DEADLINE_MS`, exported
    from a pure module), and stop through the auto-stop path if `Ready` is not reached
    in time, reason `voice connection lost (reconnect timed out)`.
  - `Ready` inside the window → one `logEvent` only, no notice, no stop, deadline
    cleared.
  - `Destroyed` → stop immediately, reason `voice connection lost`.
- Both stops route through `stopSession({ auto: true, reason })` so every existing
  receipt still applies (channel notice, DM, transcription kickoff) — no new delivery
  code, `notifyChannel` reused.
- The listener and its deadline timer are torn down in `stopSession()` alongside
  `gate.clearAll()` (`src/bot.js:487`) and the subscription destroy loop
  (`src/bot.js:488-490`).
- Pure decision logic (the deadline predicate and the two reason strings) goes in
  `src/voice-health.js` per the AGENTS.md "pure decision logic in its own module" rule.

### D2 — Bot-initiated voice changes stop the session (T2, user-approved)

- `onVoiceStateUpdate` early-returns on the bot's own id (`src/bot.js:256`:
  `if (oldState.id === deps.botUserId) return;`). Consequence: a drag/kick leaves
  `session.channelId` stale, `humanCountIn(session.channel)` reads a channel the bot
  left, and the stop notice lands in the wrong place.
- Handle the bot's own transitions: moved to another channel → stop, reason
  `bot moved to another channel`; disconnected/kicked → stop, reason
  `bot disconnected from voice`.
- Policy is **stop, not follow**. The announced venue is the recording venue; following
  silently changes what the participants consented to. Following is an explicit
  non-goal.

### D3 — One auto-stop setting, each branch on its own clock (T3, adopted default)

- Today the shared floor `if (s.nowMs - s.joinedAtMs < threshold) return { stop: false }`
  (`src/auto-stop.js:31`) gates **both** branches. A channel that empties at minute 2 at
  the default 5 min keeps "recording" 3 more minutes; at `/autostop 180` it keeps
  "recording" 3 more hours.
- **Working default (user did not answer; the shape follows their reply "autostop if
  everyone leaves OR everyone hasn't talked — same setting for both options"):** one
  threshold governs both branches, measured from each branch's own trigger instant:
  - emptied channel → stop when `nowMs - emptySinceMs >= threshold`;
  - no activity → stop when `nowMs - lastActivityAtMs >= threshold` (unchanged).
- The shared session-floor line is therefore **removed**: for the silence branch it is
  already implied (`lastActivityAt` is seeded with the join time at `src/bot.js:427`),
  and for the empty branch it is the very wait being fixed. `session.joinedAt` stays on
  the session — it is the silence branch's seed, not a gate.
- `session.emptySinceMs` is maintained by the auto-stop tick: set when `humanCountIn`
  first reports `0`, cleared when it reports `> 0`. The tick is 15 s
  (`AUTO_STOP_TICK_MS`), so the empty clock has one-tick (≤15 s) resolution — stated in
  the README, not claimed away.
- `evaluateAutoStop` stays pure: `emptySinceMs` joins its input shape. `undefined` means
  "not observed empty yet" and can never fire (the safe default: an untracked empty
  state must not stop a session).
- The members-cache fallback (`humanCount === null` → `humansWarned`, treated as
  `MAX_SAFE_INTEGER`, `src/bot.js:432-436`) is preserved verbatim: a cache blip must
  never look like an emptied channel, and must not clear `emptySinceMs` either.
- Reason strings: silence keeps `no voice activity for N min` exactly. Empty becomes
  `everyone left the voice channel (empty for N min)` — the old
  `(session ≥ N min)` clause is false under the new clock, so it is replaced
  deliberately in the same commit that changes the clock. The `/autostop` view text
  (`src/bot.js:762-766`) is updated to match.

### D4 — Retention and automatic cleanup (T4, user-approved)

- `guild_config.retention_days INTEGER NOT NULL DEFAULT 0` (**0 = off**),
  `PRAGMA user_version = 3`. `ADD COLUMN` guarded by column presence — `initSchema` is
  already column-presence based (`src/db.js:85-95`), so this is the established
  migration pattern, not a rewrite.
- Bounds `0..3650` (integer), validated by the shared `validatePatchFields`
  (`src/db.js:25-49`) so the SQLite and Map stores cannot diverge.
- New command `/retention [days]`: omit → view; `0` → off. Env seed `RETENTION_DAYS`
  (optional, default 0) with the same "env seeds, per-guild row wins" semantics as
  `TRANSCRIBE` / `AUTO_STOP_MINUTES`.
- New module `src/retention.js`:
  `sweepExpiredSessions(root, { retentionDaysByGuild, nowMs, minAgeMs, activeDir, log })`
  → `{ removed, freedBytes, skipped }`. Guards, non-negotiable:
  1. Only directories matching `discord-meetings/<guildId>/meeting-<stamp>/`. Never a
     file, never a non-matching directory.
  2. Age from the **directory-name stamp** (`meeting-YYYY-MM-DD-HH-MM-SS`, UTC, the
     exact shape `sessionDir` builds — `src/session.js:20-25`), never mtime: file-touch
     must not extend a recording's life, and a copied tree must not lose it early.
  3. Never the **active** session directory. It is passed in explicitly from a
     production accessor; `debugSession()` is a debug seam and must not be reached
     through in production code.
  4. A minimum-age floor (`RETENTION_MIN_AGE_MS`, 1 h) on top of the retention window, so
     a session whose transcription is still in flight can never be deleted.
  5. Legacy pre-3.0.0 flat `meeting-<stamp>/` dirs carry no guild attribution → never
     expired. Documented in README.
  6. Never the DB or its `-wal`/`-shm` sidecars. `sweepStaleMixTemps` (`src/tmp-cleanup.js`)
     is unchanged and still runs first.
- Triggers:
  - **Startup**: after the store is open (`src/index.js:68`) and the controller exists —
    the gateway-ready handler is the clean spot, because the sweep needs the active
    session directory. Ordering matters: `sweepStaleMixTemps` at `src/index.js:55` runs
    before the store opens and stays where it is.
  - **Daily** unref'd timer, injectable `setInterval`/`now` per the repo DI convention,
    wrapped so a failed sweep logs and never takes the gateway down. One log line per
    removed directory plus a summary (count + bytes freed).
  - The store gains `listConfigs()` (SQLite: `guild_id, …retention_days` from
    `guild_config`; Map: the rows map) so the sweep can build `retentionDaysByGuild`
    without a per-guild snowflake list. Guilds with no config row seed 0 = off.
- This is the bot's **first irreversible filesystem deletion**. README and CHANGELOG say
  so plainly, and `/retention` says what the sweep will do (age basis, floor) rather than
  just the number.

### D5 — `/status` (T5, user-approved: full content)

Ephemeral, read-only, **no files, no schema change**. New pure module `src/status.js`
with `renderStatusText(state)` plus `estimateMasterBytes({ elapsedMs, bitrate })` and
`bitrateToBytesPerSecond(bitrate)` (`env.js`'s `parseBitrate` validates only — it has no
numeric conversion; the pure logic belongs in its own module per AGENTS.md).

Content:

| Line | Source | Notes |
|---|---|---|
| session yes/no, elapsed `mm:ss`, channel name | controller `session` | elapsed from `session.joinedAt` |
| distinct speakers heard | `session.speakersHeard` (`Set<string>`) | **new**: filled in the `speaking.on('start')` handler (`src/bot.js:405-410`); survives leave/rejoin, so join→leave→rejoin counts once |
| `/autostop`, `/transcribe`, `/dm audio`, `/dm transcribe`, `/retention` | `configStore.getConfig(guildId)` | the bare-view data the mutating commands no longer need to expose |
| sidecar queue depth (running/queued) | `deps.transcribeQueue` | **new seam**: the inline `chain` closure at `src/index.js:90-99` is extracted to `src/transcribe-queue.js` (`pending()`, `running()`), injected as `deps.transcribeQueue` |
| free disk on `MEETINGS_DIR` | `fs.statfsSync(MEETINGS_DIR)` → `bavail × bsize` | try/catch; the line is omitted on failure (Windows + debian-slim both verified at build time) |
| projected master size | `deps.master?.encodeState?.()` + `estimateMasterBytes` | labelled `~` — an estimate over VBR Opus, and a *different* source in each mode (see below) |

- **`encodeState()` seam (the one forward-compat hook 3.1.0 owes 3.2.0):** `/status`
  reads `session.master?.encodeState?.()` and falls back to the v3.0.x facts
  (`packetCount`, temp-file size) when the method is absent. 3.2.0 fills it with
  `{ framesFed, outputBytes, alive }`. 3.1.0 does **not** require 3.2.0 to ship.
- Queue depth: read through `deps.transcribeQueue?.pending?.() ?? 0` so tests built
  without the dep are unchanged.
- `/status` and `/help` are the open read-only surfaces; everything that mutates is gated
  (D6).

### D6 — Permission gating (T6, user-approved)

- **Two layers, both required:**
  1. `setDefaultMemberPermissions(PermissionFlagsBits.ManageGuild)` on the builders for
     `/record`, `/stop`, `/dm`, `/transcribe`, `/autostop`, `/retention` — visible in
     Server Settings → Integrations, admin-overridable.
  2. A handler-side check replying **ephemerally** when the member lacks `ManageGuild`.
     This is the layer that is unit-testable without a gateway and the layer that holds
     when an admin loosens the default.
- `/help` and `/status` are **open** (`setDefaultMemberPermissions` not called). This is
  what makes gating the setters cost-free: members lose the ability to change things, not
  the ability to see them, because the bare-view output lives in `/status` (D5).
- **`/stop` is "session invoker OR `ManageGuild`"** — a member whose permission was
  revoked mid-session must not be trapped in a live recording. Pinned by test.
- Pure predicate in `src/permissions.js`:
  `canUseCommand(name, { memberPermissions, isSessionInvoker })`, plus
  `COMMAND_PERMISSIONS` (the single source of truth consumed by both the builders and
  the handler check).
- Invariant test: every `commandData` builder's `default_member_permissions` matches
  `COMMAND_PERMISSIONS`, mirroring the existing `DISPATCH_HANDLERS` pin in
  `test/index-wiring.test.mjs:122-125`. Adding a command without a permission decision
  must fail the suite.
- Discord permissions are per-command, not per-invocation — stated in SETUP because it is
  the reason `/status` carries this guild's settings.
- **Operational note for docs:** new command permissions take effect only on
  re-registration. The deployer PUTs at startup for `GUILD_IDS` and on `GUILD_CREATE`
  (`src/wiring.js:48-65`), so an existing guild picks them up on the next restart or
  kick/re-invite.

### D7 — Adopted working default (empty-channel reason string)

Per D3: `everyone left the voice channel (empty for N min)`, `N` = the `/autostop`
threshold in minutes. Chosen over keeping `(session ≥ N min)` because that clause becomes
factually wrong under the new clock. The existing `/everyone left/` assertions keep
matching; only the two empty-branch cases in `test/auto-stop.test.mjs` need the new
`emptySinceMs` input.

## Data model

```sql
-- guild_config, v3
guild_id              TEXT PRIMARY KEY REFERENCES guilds(guild_id),
transcribe_enabled    INTEGER NOT NULL,
dm_audio_enabled      INTEGER NOT NULL DEFAULT 1,
dm_transcribe_enabled INTEGER NOT NULL DEFAULT 1,
autostop_minutes      INTEGER NOT NULL,
retention_days        INTEGER NOT NULL DEFAULT 0,   -- NEW, 0 = off, 0..3650
updated_at            TEXT NOT NULL
PRAGMA user_version = 3
```

Downgrade: a 3.0.x binary selects an explicit column list (`src/db.js:126-128`) and writes
`user_version = 2` on open, so it should tolerate the extra column and leave
`retention_days` intact — unlike the 2.x case. **This is asserted by a test, not by docs:**
the test simulates a 3.0.x writer (the old 5-column upsert + `PRAGMA user_version = 2`)
against a v3 DB and asserts the retention value survives.

## Acceptance criteria

- **AC1** A `Destroyed` voice connection during a live session stops the session once,
  with reason `voice connection lost`, through the auto-stop path (channel notice, DM,
  transcription kickoff all still run).
- **AC2** `Disconnected` → `Ready` inside 30 s: exactly one log line, one channel notice,
  **no** stop. `Disconnected` → deadline expiry: one stop with reason
  `voice connection lost (reconnect timed out)`.
- **AC3** Bot moved / kicked: one stop, reason `bot moved to another channel` /
  `bot disconnected from voice`, one notice; no follow behavior, no second stop.
- **AC4** Emptied channel at `T` stops at `T + threshold` regardless of session age;
  a human returning before the deadline cancels it; a session that never emptied is
  unaffected; a null members cache never looks empty and never clears `emptySinceMs`.
- **AC5** `evaluateAutoStop` reason strings are exactly as pinned in D3 for both branches,
  and the two-pinned-empty-cases in `test/auto-stop.test.mjs` are updated with the new
  input added (no assertion weakened or renamed away).
- **AC6** `retention_days` round-trips through both stores with the shared validation
  (`0..3650`, integer, reject otherwise), the migration adds the column to an existing v2
  DB without touching data, and `user_version` is 3.
- **AC7** A 3.0.x-shaped writer against a v3 DB leaves `retention_days` intact.
- **AC8** `sweepExpiredSessions` deletes exactly the eligible directories: over-age per
  guild, past the 1 h floor, not the active dir, not a file, not a non-matching name, not
  a legacy flat dir, not the DB or its sidecars; returns `{removed, freedBytes}` and logs
  per-directory plus a summary.
- **AC9** Retention 0 (the default) deletes nothing; a failed sweep logs and never
  rejects into the gateway.
- **AC10** `/status` renders every D5 line for a live session and for an idle guild, the
  estimate is labelled `~`, the disk line is omitted (not fabricated) when `statfsSync`
  fails, and the sidecar queue depth is read from the injected seam.
- **AC11** Distinct-speaker counting survives join→leave→rejoin (counts once).
- **AC12** `/record`, `/stop`, `/dm`, `/transcribe`, `/autostop`, `/retention` carry
  `ManageGuild` defaults and refuse a member without it ephemically; `/stop` accepts the
  session invoker; `/help` + `/status` are open; the invariant test fails when a new
  command is added without a permission entry.
- **AC13** `package.json` 3.1.0 + matching CHANGELOG heading + README/SETUP/.env.example
  updates in the release commit; `npm test` green (`293 + new`, 0 fail) and the 4 bash
  cases green; the golden `test/fixtures/master-mix-golden.wav` is byte-unchanged.

## Out of scope

- Per-user frames buffered in RAM until finalize (`src/recorder.js:85-90, 170-175`) and
  the cap-aware bitrate at finalize (`src/deliver.js:148-153`) — both belong to the
  v3.2.0/3.3.0 streaming work; see `v3.2.0-streaming-encode.md`.
- Configurable-role permission storage (a follow-up only if `ManageGuild` proves too
  blunt).
- Bot-follows-move behavior.
- Env-seeded `/dm` toggles, per-user track delivery/zip, master transcripts (all
  deliberate 3.0.0 decisions).
- A retention *dry-run* mode, a retention report command, per-guild age overrides beyond
  the single `retention_days`.

## Risks

- **Retention is irreversible.** Name-stamp age + the 1 h floor + never-the-active-dir are
  the guards; the floor also protects a serialized transcription still in flight because
  the sidecar runs after delivery in the same process.
- **Stop-on-move is a behavior change** for anyone who expected the bot to follow. Say it
  in README/CHANGELOG; do not let it ship as a silent fix.
- **Two stops racing** (`/stop` + a voice-state stop + the auto-stop tick): `stopSession`'s
  `if (!current) return null` (`src/bot.js:481-482`) is the existing guard, and the new
  listener/timer teardown must run in `stopSession` so a dead connection cannot fire
  later.
- **Permission gating only applies after re-registration** — documented, not worked
  around.
- **`/status` disk line** depends on `fs.statfsSync`; verified on Windows + the Debian
  slim image, omitted on failure rather than guessed.
- **15 s tick resolution** on the empty-channel clock is inherent to the tick; documented.
