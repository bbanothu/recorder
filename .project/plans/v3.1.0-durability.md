# v3.1.0 operational durability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the recorder honest about lost audio, stop it from recording an empty channel for the whole auto-stop threshold, add opt-in retention, add an open read-only `/status`, and gate the mutating commands behind `ManageGuild`.

**Architecture:** Six contained changes to existing seams — a new `connection.on('stateChange')` subscription routed through the existing auto-stop path; bot-own voice-state transitions handled where they are currently returned away; `evaluateAutoStop` given a per-branch clock instead of a shared session floor; a new name-stamp retention sweeper behind a new SQLite column; a pure `renderStatusText` module fed by two extracted seams (sidecar queue counter, master `encodeState()`); and one pure permission predicate consumed by both the command builders and the dispatch guard.

**Tech Stack:** Node.js ≥ 22.13 ESM (observed `v26.7.0`), discord.js v14 + `@discordjs/voice`, `node:sqlite`, `node --test` (`test/*.test.mjs`), bash harness `test/scripts/build-and-push.test.sh`.

Spec: `.project/specs/v3.1.0-durability.md` (decisions D1–D7, AC1–AC13).

**Baseline:** `master` at `39f85de` (the `docs:` commit carrying this plan; the handoff
briefs it supersedes are in `6c5dbfa`), version **3.0.1**, **293 node tests + 4 bash cases green**, clean tree (`origin` exists; nothing is pushed). Target `3.1.0` (minor: new commands, new env var, new column — backward compatible).

**Branch:** `feat/v3.1.0-durability`, cut from `master` **after** the v3.1.0 + v3.2.0 spec/plan `docs:` commit lands (the repo's history: docs on `master`, implementation on `feat/*`). Parent SHA and the spec/plan commit SHA are recorded in Task 0.

**Protocol:** one task at a time; RED before GREEN; every task gets an independent spec review and then a quality review; the controller verifies every implementer self-report against the live repo (never trusts the report); a failed review gets one bounded fix cycle. Commit per task on the feature branch — **never on `master`** (the operator merges).

## Task 3 — T3: the emptied channel gets its own clock

**Files:** `src/auto-stop.js`, `test/auto-stop.test.mjs`, `src/bot.js`, `test/bot.test.mjs`.

1. **RED (pure)** — `evaluateAutoStop({ nowMs, joinedAtMs, lastActivityAtMs, emptySinceMs, humanCount, thresholdMs })`:
   - remove the shared floor line (`src/auto-stop.js:31`); evaluate each branch against its own clock;
   - empty branch: `humanCount === 0 && emptySinceMs != null && nowMs - emptySinceMs >= threshold` → `{stop:true, reason:`everyone left the voice channel (empty for ${threshold/60_000} min)`}`;
   - silence branch: unchanged string `no voice activity for N min`;
   - `emptySinceMs == null` (not observed empty) ⇒ the empty branch can never fire;
   - empty AND silence ⇒ the everyone-left reason wins (existing preference, kept).
   Cases: emptied at `T` → stop at `T+threshold` and not one ms earlier; human returns → `emptySinceMs` cleared by the caller ⇒ no stop; silence-only session still respects its threshold; an emptied session that is **younger than the threshold** now stops (this is the defect being fixed — name the case after that); `emptySinceMs == null` with `humanCount === 0` ⇒ no stop; cache-null (`humanCount: MAX_SAFE_INTEGER`) ⇒ no stop.
   - **Update** the two existing cases that feed `humanCount: 0` (`test/auto-stop.test.mjs:19-23`, `:41-44`) by adding `emptySinceMs`; keep their `/everyone left/` assertions. The `does NOT stop before 5 min in channel` case (`:31-34`) must stay green **unchanged** (`emptySinceMs` absent ⇒ no stop).
2. **RED (bot)** — the tick: first `humanCount 0` observation sets `session.emptySinceMs`; a later `> 0` clears it; the cache-null path (`src/bot.js:432-436`) neither sets nor clears it and still logs once (`humansWarned`). Assert `evaluateAutoStop` receives `emptySinceMs` and the stop reason is the new string.
3. **GREEN** — maintain `session.emptySinceMs` in the tick and pass it to `evaluateAutoStop`; update `/autostop`'s view text (`src/bot.js:762-766`) to describe the per-branch clock (emptied → N min after it emptied; silence → N min after the last packet; ≤15 s tick resolution).
4. Report every existing test changed in `test/bot.test.mjs` (the `/autostop` view assertion will change — that is expected and must be listed).

**Commit:** `fix: stop an emptied voice channel on its own clock instead of the session floor`

## Task 5 — T4b: the expiry sweep and its triggers

**Files:** `src/retention.js` (new), `test/retention.test.mjs` (new), `src/bot.js`, `src/index.js`, `test/bot.test.mjs`.

1. **RED (pure-ish module, temp dirs, no timers)** — `sweepExpiredSessions(root, { retentionDaysByGuild, nowMs, minAgeMs, activeDir, log })` → `{ removed, freedBytes, skipped }`.
   Build a `mkdtempSync` tree per case. Cases (each names its own fixture):
   - **deletes**: `discord-meetings/<guild>/meeting-<stamp>/` whose stamp is older than that guild's `retentionDays` and older than `minAgeMs` → removed, `freedBytes` equals the sum of the removed files' sizes, one log line per directory.
   - **keeps**: inside the retention window; inside the 1 h floor even when far past retention; the active directory (passed as `activeDir`) even when over-age; a guild with `0`; a guild absent from the map; a legacy flat `discord-meetings/meeting-<stamp>/` (no guild layer); a loose file directly under the guild dir; a non-matching directory name (`meeting-<bad stamp>`, `notes/`); the DB and its `-wal`/`-shm` sidecars when the root also holds them.
   - **never follows symlinks** (skip on Windows if `symlinkSync` needs privileges — say so in the report rather than silently dropping the case).
   - unreadable subtree → the rest of the sweep still returns (mirror `sweepStaleMixTemps`'s resilience).
   - **age is the name stamp, not mtime**: `utimesSync` a kept directory to look ancient and assert it survives; `utimesSync` an over-age directory to look fresh and assert it is still removed.
2. **GREEN** — implement with `readdirSync`/`rmSync(recursive)` and directory sizes via a bounded recursive stat; no `debugSession()` access anywhere in `src/retention.js` or `src/index.js`.
3. **RED (production accessor)** — controller exposes `activeSessionDir()` → `session?.recorder?.dir ?? null` (a production accessor, deliberately **not** `debugSession()`). Case: null when idle, the recorder's dir while recording, null again after stop.
4. **RED (triggers)** — `src/index.js`: one startup sweep after the store is open and the controller exists (in the `ClientReady` handler), one daily unref'd timer with injectable `setInterval`/`now`, each wrapped so a throw logs and never rejects. Case with an injected fake timer + a throwing store: exactly one log, no rejection, the gateway handler chain survives.
5. `npm test` green; report counts and any test changed.

**Commit:** `feat: sweep expired session directories per guild retention`
