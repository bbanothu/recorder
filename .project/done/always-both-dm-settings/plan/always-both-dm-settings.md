# Always-BOTH Recording + Per-Guild DM Settings Implementation Plan (v3.0.0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every session records per-user tracks **and** the master mix, transcription always runs on the per-user tracks, recordings land under a per-guild directory, and each guild controls with `/dm` whether `/stop` DMs audio files and whether it DMs transcript files.

**Architecture:** Mostly **deletion plus one small seam**. The dual audio sink already exists as a single boolean (`recorder.js:32` `writePerUserFiles`; `bot.js:334-356` `masterOnly` → `master` + `writePerUserFiles: !masterOnly`), so "always BOTH" removes `RECORDING_TYPE` (env, `/record_type`, DB column) and makes the master unconditional. The per-user-only transcription route already exists (1.7.0 combined render at `bot.js:700-715`), so removing `TRANSCRIBE_MODE` deletes the master route and its now-orphaned machinery (`attribution.js`, `speaking-log.js`). New surface is one `/dm` command, two `guild_config` booleans behind an idempotent column-presence migration, a `guildId` component in `sessionDir()`, and a two-artifact delivery split in `deliver.js` (master DM + tracks DM, each cap-checked, independently suppressible).

## Task 3b: Bound master-mix memory to O(packet) (user-mandated; RED → GREEN)

Objective: the master mix must stop holding the session in RAM. `MasterMix` accumulates a stereo `Float32Array` timeline indexed by absolute session offset: 48 kHz × 2ch × 4 B = **384 KB/s ≈ 23 MB/min ≈ 1.38 GB/h**, doubling transiently (peak ≈ 2×) — so a 2-hour meeting can demand ~2.8 GB, and a late first speaker allocates in proportion to *elapsed* time. Always-BOTH (Task 3) made that universal; `186b95d` made the resulting `RangeError` non-fatal, and this task removes the trigger. Discovered by the Task 3 quality review — the spec's original Risks section priced disk and CPU but not RAM.

Approach (user-selected, option B — sparse temp PCM, one ffmpeg pass): accumulate the mix into a **temp file beside the session dir** (`<dir>/master-<ts>.mix.tmp`) using positional read-modify-write per packet, keeping the interleaved **float32 stereo** layout so the summation math is bit-identical to today (int16-on-disk would halve it but changes accumulation). Silence becomes a *sparse hole* — seeking past the end reads as zeros, so gaps cost nothing to write. At `finalize`, stream the temp file in bounded chunks through the existing `softLimitToInt16` into the real `.wav`, then the existing ffmpeg encode, then unlink both. `finalize`'s contract (ogg path | `.wav` fallback | `null` after a loud log) is unchanged.

- Modify: `src/master-mix.js` (`this.mix`, `#ensureLength`, `#addAt`, `#reset`, `finalize`), `src/wav.js` (streaming writer beside `writeWavFile`), plus `src/bot.js`/`src/index.js` only if a new IO seam must be threaded
- Modify tests: `test/master-mix.test.mjs` (+ `test/wav.test.mjs` if it exists)
- **Explicitly OUT:** the per-user `frames` array in `src/recorder.js` / `src/ogg-mux.js` (~21 MB/h per user) — deferred to a later release per spec decision 11; do not touch it here.

## Risks / pitfalls for the implementer

- **Order matters.** Task 3 before Task 4 (nothing may read `recordType` when the column dies — Task 3 deletes the binding, the sidecar block and the seed dep in one commit), Task 4 before Task 5 (env seeds are read by the store until then). **Task 4 owns the stop-time gate rewrite** — the store loses `transcribeMode` there, so the gate must be collapsed to the per-user route in the same task; **Task 6 is deletion-only**. Never commit a state where the store writes a column the schema lacks, or where the gate reads a store field that no longer exists.
- **Guild-id validation lives ONLY in `sessionDir()`.** Do not add a `guildId` guard in `bot.js`: bot-test fixtures pass `guildId: 'g1'` (which must be tolerated at the controller layer) — only the path builder validates the snowflake.
- **Every session now constructs a real `MasterMix`** (`bot.js:337`, unconditional even when a harness does not inject `createMasterMix`). Expect stray "master mix started/skipped" log lines in captured-output tests; assert on the specific line or pattern you own, never on the whole captured log.
- **`ALTER TABLE … DROP COLUMN` needs SQLite ≥ 3.35** — fine here (3.53.4 / Node ≥ 22.13 bundles ≥ 3.46), but the guard must be column-presence based, not `user_version`-based, so a fresh DB and a legacy DB both converge.
- **`node:sqlite` has no `.pragma()` helper** — use `db.exec('PRAGMA …')` to write, and the proven prepare form to read: `db.prepare('PRAGMA user_version').get().user_version` and `db.prepare("PRAGMA table_info('guild_config')").all()` (both verified on Node 26.7.0 / SQLite 3.53.4; the `PRAGMA user_version` prepare form is already exercised at `test/db.test.mjs:245`). No `SELECT * FROM pragma_…` fallback.
- **opusscript now decodes on every session.** `MasterMix.push` decodes every packet via opusscript (`master-mix.js:76-114`); today that runs only in MASTER mode, but always-BOTH makes it universal, adding CPU to every recording. No code change — budget host headroom (same advice as `WHISPER_CPU_THREADS`) and note it in the release docs if load matters.
- **Never DM a non-`.ogg` master.** The WAV fallback is stereo 48 kHz 16-bit (~11.5 MB/min) and blows the 25 MiB cap in ~2 minutes; the design treats extension as the ffmpeg-failure signal.
- **`delivered` vs `suppressed`.** A suppressed audio DM must not surface as "Delivery failed" in the channel notice; that distinction is a pinned test.
- **Guild-id validation will break naive test fakes** — use real-shaped 17-20 digit ids in fixtures; do not relax the regex to make a test pass.
- **`test/bot.test.mjs` is 2,546 lines** — when a behavior flips (`masterOnly`, the `/record` tip, the stop tail), expect several existing cases to need updating; update them to the new contract rather than preserving the old assertion.
- **Do not touch** `discord-meetings/` or `.env`; `git status` must be clean of both before every commit.
