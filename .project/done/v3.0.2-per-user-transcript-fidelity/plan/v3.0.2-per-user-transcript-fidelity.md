# v3.0.2 per-user transcript fidelity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a captured per-user track reach the transcript at its true meeting time — no speaker silently dropped, no silence missing from the audio.

**Architecture:** The recorder already receives every packet with an arrival timestamp and the master mix already times packets on a 20 ms grid; today the recorder throws that away and appends packets back-to-back, and it writes packets the session's own decoder rejected. This release (a) keeps only decoder-accepted packets in a track, (b) fills inter-packet gaps with a shared libopus silence frame so a track spans the real meeting timeline, (c) writes an append-only `timeline-<stamp>.jsonl` recording the meeting start, each track's creation delta, every speech burst, and join/leave/reconnect events, and (d) canonicalises a track through ffmpeg before the whisper sidecar so no container-level quirk can silently truncate a transcript.

**Tech Stack:** Node.js ≥22 ESM, `node:test`, `@discordjs/voice` 0.19.2, `opusscript` (decode + the silence frame), ffmpeg CLI (`pcm_s16le` 16 kHz mono transcode, `libopus` master encode), faster-whisper 1.2.1 sidecar (PyAV reader).

**Spec:** `.project/specs/v3.0.2-per-user-transcript-fidelity.md` (decisions D1–D9, AC1–AC12).

**Baseline (verified at planning time, 2026-10-02; re-pinned by Task 0 before any work):** `master` at the `docs:` commit that last edited this plan (`e172575` or later), version **3.0.1**, clean tree. `origin` exists (GitHub) but nothing is pushed. `npm test` = **293 node tests / 51 suites + 4 bash cases, all pass**. Golden `test/fixtures/master-mix-golden.wav` must stay byte-unchanged.

**Branch:** `fix/v3.0.2-per-user-transcript-fidelity`, cut from `master` after this spec/plan land as a single `docs:` commit. **Version before → after: `3.0.1` → `3.0.2`** (patch; ships before the undispatched v3.1.0/v3.2.0 specs, which keep their numbers).

| Decision | Verdict |
|---|---|

| Canonicalising through ffmpeg before the sidecar (rather than only fixing the write path) | **accepted**; it is the only fix that repairs already-recorded sessions |

| Grouping many silence frames into one Ogg page (~10× cheaper padding) | **deferred** (measured potential; not this patch) |
| Deriving transcript times from the timeline file instead of the audio | **declined** — with D1 the audio carries the clock; a second mapping layer is redundant |

- Test: `test/timeline-pad.test.mjs`, `test/opus-silence.test.mjs`, `test/recorder.test.mjs`, `test/bot.test.mjs`

- [ ] RED (`test/timeline-pad.test.mjs`): `gapFrames({ prevAtMs: 1000, atMs: 3000 })` → **`99`** (a 2 s gap is 100 slots, and the previous packet already covered its own, so 99 pad frames follow it); `gapFrames({ prevAtMs: 1000, atMs: 1030 })` → `0` (below the 40 ms threshold: jitter, not silence); `gapFrames({ prevAtMs: 1000, atMs: 1040 })` → `0` (exactly at threshold, not above); `gapFrames({ prevAtMs: 1000, atMs: 3051 })` → **`102`** (nearest whole frame: 102.55 rounds to 103 slots, minus 1); a backwards clock (`atMs < prevAtMs`) → `0`.
- [ ] Run: `node --test test/timeline-pad.test.mjs` → fails (`Cannot find module '../src/timeline-pad.js'`).
