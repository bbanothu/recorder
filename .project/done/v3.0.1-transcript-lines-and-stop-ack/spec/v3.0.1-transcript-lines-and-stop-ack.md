# Design: v3.0.1 — transcript line breaks + immediate `/stop` acknowledgement

Status: **Approved** (user decisions 2026-09-27)

## Goal

Two defects found in production use of 3.0.0:

1. **Transcript entries collapse onto one line in markdown renderers.** The
   transcript `.md` is DM'd as an attachment; Discord's in-app preview renders
   it as markdown, where a single `\n` is a *soft* break and consecutive lines
   merge into one paragraph. The operator saw every timestamp run together in
   Discord but correct breaks after downloading the file (a plain-text viewer).
   The file has exactly one consumer — a human reader; no parser in `src/` or
   `test/` splits it.
2. **`/stop` shows nothing until the whole stop pipeline finishes.** That
   pipeline includes `MasterMix#finalize()` — the ffmpeg encode, ~37 s per hour
   of meeting — so the operator waits in silence after typing the command.

## Key decisions (user-approved)

1. **Blank line between entries.** `renderCombinedTranscriptMarkdown` joins
   entries with `\n\n` instead of `\n`, so every timestamped entry becomes its
   own markdown block. This is the only separator that survives soft-break
   collapsing, and in raw text it differs by exactly one blank line. The rest of
   the transcript's shape (header, `[mm:ss] **Name:** text`, ordering,
   nothing-spoken body) is unchanged.
2. **The immediate ack IS the interaction reply, and the outcome later EDITS
   that same ephemeral message.** The operator sees `Stopped. …` at once; when
   the background work settles, that same message becomes the truthful outcome
   (`Stopped. Sent the master mix to your DMs.` / `Stopped. Nobody spoke — no
   files.` / `Stopped. Delivery failed — check the console output…`).
3. **The ack adapts to the guild's settings** so it never promises a DM that
   will not arrive. Inputs are the stop-time snapshot: `dmAudioEnabled` (audio
   DM), and `transcribeEnabled && dmTranscribeEnabled` (transcript DM — the
   produce-gate wins, `transcribeEnabled` false means no transcript exists at
   all). Exact strings are pinned in the plan; the user's verbatim string is
   case 1.
4. **The ack is sent BEFORE any slow work.** New `/stop` order: read the config
   snapshot → `interaction.reply({content: ack, flags: Ephemeral})` →
   `void stopSession({interaction})` with a `.catch` that logs. No
   `deferReply`: deferring then editing shows "thinking…" through the entire
   encode, which is the defect being fixed. `stopSession` keeps its internal
   order (teardown → `recorder.stop` → master `packetCount` read → `finalize`
   → delivery → channel notice → transcription kickoff) but **drops its
   manual-mode `throw deliveryError` tail** — nothing awaits it any more, so a
   delivery error surfaces as (a) the outcome edit, (b) the channel notice,
   (c) a loud log line instead of a thrown error.
5. **`session = null` still happens first inside `stopSession`**, so a new
   `/record` can start while the previous meeting is still encoding. Per-session
   directories make the overlap safe; the `.mix.tmp` sweep stays startup-only
   (unchanged, one session per process).
6. **Auto-stop is unchanged.** It has no interaction to reply to; it keeps its
   channel notice, DM and log-only failures. The ack helper is manual-only.
7. **Failure isolation.** The background continuation must never produce an
   unhandled rejection. `deliverSession`'s outcome line already targets the
   ephemeral message via `editReply`; if the interaction token has expired the
   edit is caught and logged, and the channel notice still carries the truth.

## Behavior spec

### Transcript (`src/transcribe.js`)

`renderCombinedTranscriptMarkdown` — entries joined with `\n\n`; header and the
`_No speech detected._` body unchanged. Pinned by a test asserting no two
entries are separated by a lone `\n`.

### `/stop` (`src/bot.js`)

`stop(interaction)`:
- no session → unchanged (`Nothing recording.`, ephemeral reply).
- otherwise → snapshot config → reply the ack (ephemeral) → background
  `stopSession({interaction})` whose rejection is logged, never thrown.
- the stop-time snapshot is read ONCE, synchronously, and threaded into
  `stopSession({interaction, stopConfig})`: that single snapshot feeds BOTH the
  delivery gates and the transcription gate, so a `/transcribe` or `/dm` change
  landing DURING the encode no longer affects that session — a change made
  before `/stop` still does (the snapshot predates the ack).

`stopSession`: unchanged except the removal of the manual-mode `throw
deliveryError` tail. The threaded snapshot also removes the mid-encode `/dm`
drift that let the ack promise a DM the pipeline then suppressed.

New pure module `src/stop-ack.js`: `stopAckText({dmAudioEnabled,
transcribeEnabled, dmTranscribeEnabled})` → the ack string. Pure decision logic
in its own module per AGENTS.md, unit-tested without wiring.

### Docs (`README.md`, `SETUP.md`, `CHANGELOG.md`, `package.json`)

Transcript: one entry per line (blank-line separated, so markdown previews show
every timestamp on its own line). `/stop`: acknowledges immediately, then the
recording is encoded and delivered in the background — the DM arrives when the
encode finishes, and the ack message updates with the outcome. Version `3.0.1`
(patch: two fixes, no env or API surface change).

## Acceptance criteria

- **AC1** `renderCombinedTranscriptMarkdown` separates every entry with a blank
  line; no entry is separated from the next by a lone `\n`; content assertions
  preserved; suite + golden unchanged.
- **AC2** A two-speaker, three-segment fixture renders one markdown block per
  entry (blank line after the header, blank line between all entries).
- **AC3** `/stop` replies with the ack BEFORE any finalize work — proven with a
  `master.finalize` that never resolves: the reply must already have been sent.
  The pin must FAIL if the reply moves after `finalize`.
- **AC4** The four-case ack matrix is pinned, case 1 exactly the user's string.
- **AC5** The background outcome edits the same ephemeral message for every
  terminal state: delivered / nobody-spoke / master-write-failed / suppressed
  (`/dm audio FALSE`) / delivery-failed.
- **AC6** A background delivery failure logs, never rejects, and the channel
  notice still reports the true tail.
- **AC7** Auto-stop behaviour is unchanged: the auto-stop path, its own tests,
  and every auto-stop-specific assertion are untouched (no ack, no edit).
  Manual-stop tests may gain a harness flush, because `/stop` no longer awaits
  the pipeline.
- **AC8** `package.json` 3.0.1 + matching CHANGELOG heading + README/SETUP
  updates in the release commit; `npm test` green.

## Out of scope

- Per-user `frames` RAM buffering / streaming `ogg-mux` (v3.0.0 spec decision
  11, a 3.x follow-up).
- Any change to the DM policy, the recording pipeline, the encode settings, or
  the transcription sidecar.
- A retention/cleanup job for recorded files.

## Risks

- **Interaction token expiry** during a very long encode (>15 min): the outcome
  edit fails, is logged, and the channel notice still tells the truth (AC6).
- **Double `/stop`:** the second sees `session === null` and answers `Nothing
  recording.` while the first meeting is still encoding. Already the case for
  the processing window; acceptable.
- **"Shortly" is load-bearing:** a long meeting's encode takes minutes, not
  seconds. README's known-limits note already carries the measured ~37 s per
  hour; the ack wording must not claim otherwise.
- **The ack states the pipeline's intent, not a guarantee.** The transcript
  clause can be broken by a session whose tracks are all under
  `MIN_TRACK_FRAMES`, whose sidecar runs all fail, or when python/faster-whisper
  is absent — all log-only outcomes. The audio clause can be superseded by a
  hard delivery failure, which now edits the ack to the failure line.
- **Interaction-token expiry (>15 min encode):** the master mix IS sent (the DM
  is not token-bound) but the outcome edit fails, so the ack stays stale and the
  channel notice reports "Delivery failed" although the mix was delivered —
  pre-existing `deliver.js` behaviour, documented here rather than claimed
  otherwise.
