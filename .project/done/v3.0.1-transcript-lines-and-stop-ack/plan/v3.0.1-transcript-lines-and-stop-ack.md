**Files:** `src/transcribe.js`, `test/transcribe.test.mjs`. Nothing else.

   00:07), assert the rendered output has a blank line before every entry: the
   output contains `\n\n[00:03] `, `\n\n[00:07] `, `\n\n[00:09] `, and **no entry

## Task 2 — immediate `/stop` acknowledgement, backgrounded processing

**Files:** `src/stop-ack.js` (new), `test/stop-ack.test.mjs` (new), `src/bot.js`,
`test/bot.test.mjs`, plus `test/transcribe.test.mjs` for step 8 only.

1. **RED (pure helper)** — `stopAckText({dmAudioEnabled, transcribeEnabled,
   dmTranscribeEnabled})` returns, exactly:
   - audio on + transcript DM on →
     `Stopped. Voice recording and transcription will be sent to your DMs shortly.`
   - audio on + no transcript DM →
     `Stopped. Voice recording will be sent to your DMs shortly.`
   - audio off + transcript DM on →
     `Stopped. Transcription will be sent to your DMs shortly; the recording is kept on disk (/dm audio TRUE to re-enable).`
   - audio off + no transcript DM →
     `Stopped. Files will be kept on disk (audio DMs are off; /dm audio TRUE to re-enable).`
   - `transcribeEnabled: false` ⇒ never promise a transcript, even when
     `dmTranscribeEnabled` is true (the produce-gate wins).
2. **RED (order)** — with `master.finalize` stubbed to a promise that never
   resolves, `await stop(interaction)` must already have replied with the ack:
   record call order and assert reply-before-finalize. This pin must FAIL if the
   reply is moved after `finalize`.
3. **RED (outcome)** — the outcome edits the **same** ephemeral reply for every
   terminal state: delivered / nobody spoke / master write failed / suppressed
   (`/dm audio FALSE`) / delivery failed.
4. **RED (isolation)** — a background delivery failure is logged and does not
   reject; the channel notice still fires with the true tail.
5. **GREEN** — restructure per spec decision 4: snapshot config in the handler,
   reply the ack, then `void stopSession({interaction}).catch(logEvent)`;
   remove the manual-mode `throw deliveryError` tail. Keep everything else
   (teardown order, the before-`finalize` `packetCount` read, delivery,
   channel notice, transcription kickoff) byte-identical.
6. Update the existing tests that pin the old contract (deferred reply, error
   rethrow) and **list each one** in the report — nothing else weakened.
7. `npm test` green; golden unchanged; `git status` clean.
8. **Carry-in from the Task 1 spec review (test-only, no production change):** the
   Task 1 pin's `/[^\n]\n\[/` scan false-positives when ASR text itself contains
   a newline followed by `[` (faster-whisper `s.text` is passed through raw), and
   there is no one-entry transcript case. Anchor the pin to line starts — no line
   may begin with `[` unless the previous line is blank — and add the one-entry
   case (a single entry after the header, blank-line separated).

**Commit:** `feat: acknowledge /stop immediately and process the recording in the background`

**Review note:** the order pin must be mutation-proven (move the reply after
`finalize` → it fails).

## Task 2b — fix cycle from the Task 2 quality review

**Files:** `src/bot.js`, `src/stop-ack.js`, `test/bot.test.mjs`,
`test/stop-ack.test.mjs`, `test/transcribe.test.mjs` (only if a step needs it).

1. **Terminal signal on hard failures (review's major).** `deliver.js` rethrows
   non-forbidden errors BEFORE it replies, and any throw before the channel
   notice (e.g. `recorder.stop()`) leaves no notice either. With the manual-mode
   rethrow removed, those classes leave the ack message saying "…shortly."
   forever — only the console knows. Before this change they surfaced as an
   ephemeral "Something went wrong." from `index.js`'s command-error handler.
   That operator visibility must not be lost.
   **Fix:** in the background continuation's `.catch` (the `void
   stopSession(...).catch(...)` in `stop()`), after logging, best-effort edit
   the ack message to a shared, single-source failure line —
   `Stopped. Something went wrong processing the recording — check the console output.`
   — via `interaction?.editReply(...)` guarded with `.catch(() => {})` so an
   expired token cannot throw. Correct the false comment at `src/bot.js:487-488`
   to describe what actually happens.
2. **Pin it.** A NON-forbidden delivery failure (e.g. a `user.send`/`dmInvoker`
   throw with code 50035, or a `statSync` ENOENT master) must: edit the ack to
   the failure line, log the error, and never reject. Separately pin that an
   expired-token edit failure stays caught and log-only — the ack may remain
   stale in that case. That is inherent (the DM itself is not token-bound) and
   must be documented, not claimed away.
3. **Thread one snapshot (minor).** `stop()` passes its snapshot on:
   `void stopSession({ interaction, stopConfig })`, and `stopSession` uses
   `opts.stopConfig ?? configStore.getConfig(current.guildId)` (auto-stop keeps
   its own read). This removes the proven mid-encode `/dm` toggle drift, where
   the ack promised a DM that `deliver` then suppressed, and makes the "same
   stop-time snapshot" comment literally true. Update any test that depended on
   the second read.
4. **Doc honesty (minor).** Spec decisions 3/7 over-claim; the spec's Risks
   section gains the two limits (transcript promises broken by all-tracks-under-
   `MIN_TRACK_FRAMES` / all-sidecar-fail / sidecar-absent; token-expiry leaves
   the ack stale while the notice reports "Delivery failed" although the mix was
   sent). **The four ack strings stay unchanged.**
5. `npm test` green; golden unchanged; report every existing test changed.

**Commit:** `fix: keep an operator-visible terminal state when /stop processing fails`

## Task 3 — release 3.0.1, verification, archive

1. **Polish commit** — the three minors both Task 2b reviews left open:
   - **(a) Stale comment** at `src/bot.js` ~594: it still says the transcription
     gate "is re-read from the guild's config at STOP time". It is no longer
     re-read — the threaded snapshot taken when `/stop` was acked feeds the whole

     await only the ack, and assert the observed call order while `finalize` is
     still pending. A mutation must produce an assertion failure, not an
     unbounded wait.
   - **(c) Double-edit hazard.** The sink at `stop()`'s background `.catch` could
     overwrite an outcome that already landed (`Stopped. Sent the master mix to
     your DMs.`) if anything throws after the notice. Track per-interaction ack
     state (a WeakSet in the factory, or a small state object threaded into
     `stopSession`) so the generic failure line can only replace the ack when
     nothing more specific has been written. Latent today — keep it cheap and
     pinned.
